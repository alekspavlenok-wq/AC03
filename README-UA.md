# Folia Xeon 26.3 (локальна збірка)

Це локальна кастомна збірка з наданого архіву PaperMC Folia гілки ver/26.2.x. Назва 26.3 — версія цього форку; код протоколу, mcVersion і API лишаються 26.2. Це потрібно, щоб сервер не видавався сумісним із Minecraft 26.3, доки в архіві є лише код 26.2.

## Поточний профіль заліза

Скріншот показує Xeon E5-2660 v4: 14 фізичних ядер / 28 логічних процесорів і 32 ГБ RAM. Folia рекомендує щонайменше 16 фізичних ядер, тому не варто очікувати масштабування як на великому серверному процесорі. Folia особливо допомагає, коли гравці розподілені по багатьох незалежних регіонах. Гравці поруч в одному регіоні лишаються обмежені швидкістю тіку цього регіону.

GT 730 не прискорює серверний тікінг: сервер не рендерить кадри й не має графічного навантаження, яке можна передати цій карті. Запуск не намагається вигадано завантажити GPU. Параметр ActiveProcessorCount зменшує кількість процесорів, яку JVM використовує для автоматичного підбору деяких пулів, але не є жорсткою прив'язкою CPU.

## Збірка ядра на Windows

Потрібен JDK 25 у PATH і доступ до інтернету, бо Gradle/Paperweight мають завантажити залежності та вихідний код Paper. З кореня цього каталогу:

    ./gradlew.bat applyAllPatches
    ./gradlew.bat :folia-server:createPaperclipJar

Якщо wrapper ще не завантажив Gradle, він зробить це під час першого запуску. Готовий серверний JAR шукай у folia-server/build/libs. Якщо назва task зміниться з новою версією Paperweight, подивись командою ./gradlew.bat tasks --all та знайди task створення Paperclip JAR.

Перший запуск створить eula.txt і зупиниться; якщо погоджуєшся з EULA, вистав eula=true та запусти знову. Після створення конфігів злий фрагменти з ops/config у config/paper-global.yml та server.properties. Не замінюй цими фрагментами весь конфігураційний файл.

## Запуск із використанням ресурсів ПК

Створи окрему чисту папку сервера поза репозиторієм. Візьми folia-paperclip-26.3.0-mc26.2.local-SNAPSHOT.jar з folia-server/build/libs. Скопіюй у папку сервера файл ops/start-server-memory-balanced.bat і сам Paperclip JAR. Batch-файл знаходить server.jar або folia-paperclip-*.jar поруч із собою; запускай його подвійним клацанням:

    start-server-memory-balanced.bat

Batch-файл задає початкову купу JVM 1 ГБ, максимум 28 ГБ і повідомляє JVM про всі 28 логічних процесорів. Xmx є верхньою межею heap, а не обсягом RAM, який Java обов'язково займе. На комп'ютері з 32 ГБ RAM ліміт 28 ГБ залишає небагато місця Windows і пам'яті JVM поза heap; якщо система почне активно використовувати файл підкачки, зменш Xmx до 20–24 ГБ.

Назва серверного бренду, яку клієнт показує у F3, встановлена як `AC03`. Це лише назва збірки; протокол і версія Minecraft лишаються 26.2.

## Стартові налаштування

Профіль ops/config/paper-global-fragment.yml задає 12 регіональних потоків, 4 потоки роботи з чанками та 2 потоки I/O. Самі потоки зазвичай не пояснюють різницю в кілька гігабайтів. Якщо світ попередньо згенерований, зменшується потреба в одночасній генерації чанків. Фрагмент server.properties зберігає дистанції 8/6, щоб не створювати надмірну кількість активних чанків. Змінюй параметри по одному після спостережень за MSPT/TPS, RAM і завантаженням CPU.

Кількість гравців наперед не задаю: вона залежить від плагінів, стилю гри, кількості сутностей, генерації чанків і того, наскільки розподілені гравці.

## Gradle-плагін

Gradle-проєкт CPU-плейсхолдера розміщений у plugin-template. Він використовує Java 25, Folia API 26.2.build.7-beta та PlaceholderAPI 2.12.3:

    cd ./plugin-template
    ./gradlew.bat build

JAR `folia-cpu-placeholder-1.0.0.jar` буде в plugin-template/build/libs; поклади його разом із PlaceholderAPI у plugins сервера й перезапусти сервер. Плейсхолдери: `%foliacpu_usage%` — відсоток зайнятості CPU процесом у перерахунку на одне логічне ядро (100% = одне повністю зайняте ядро; значення може бути більшим за 100%), `%foliacpu_total%` — частка загальної потужності всіх логічних процесорів, `%foliacpu_cores%` — еквівалентна кількість зайнятих логічних ядер. Значення оновлюються раз на дві секунди. У plugin.yml зазначено folia-supported: true.

У HelloFoliaPlugin.java команда /foliahello показує безпечний шаблон: повільну роботу запускай через AsyncScheduler, а звернення до гравця повертай через його EntityScheduler. Не звертайся до світу, сутностей чи блоків з async-потоку. Для роботи з координатою використовуй RegionScheduler; для глобальних серверних задач — GlobalRegionScheduler. Дані плагіна, які читаються з кількох регіонів, потребують синхронізації або потокобезпечних структур.

Для компіляції проти майбутньої зміни API саме цього форку опублікуй його API у Maven Local після успішної збірки командою publishToMavenLocal, тоді вистав foliaApiVersion у plugin-template/gradle.properties рівним 26.3.0-mc26.2.local-SNAPSHOT. Поки API форку не змінений, публічна версія 26.2 відповідає цій базі.

Не запускай ядро публічним сервером до перевірки плагінів і резервного копіювання світів. Перевір сумісність кожного плагіна з Folia окремо.
